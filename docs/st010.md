# ST010 cartridge support

ST010 cartridges now load with their board map and eight math commands. The ordinary ROM command detects the device from mapping byte $30 and cartridge type $F6. ROM-size byte $09 identifies ST011 instead; that device remains unsupported.

```powershell
.\out\build\release\frontend\snes_frontend.exe "C:\games\game.sfc"
```

## Memory and registers

ROM occupies the upper half of each cartridge bank, with 32 KiB LoROM addressing and ROM-size mirroring. Unused lower-bank windows stay open. Console WRAM retains banks $7E-$7F. The usual LoROM SRAM windows at $70-$7D and $F0-$FF share the device's 4 KiB RAM; small-ROM layouts also mirror SRAM into the upper bank halves.

| Window | Behavior |
| --- | --- |
| $60-$67:$0000-$3FFF | Reads return $80. A write enables the command registers. |
| $68-$6F:$0000-$7FFF | Shared RAM, mirrored every 4 KiB. Offsets $020/$021 expose command and execution registers. |
| Register $020 | Selects a command when control is enabled. Its write also reaches backing RAM. |
| Register $021 | Bit 7 starts the selected command when control is enabled. Completion clears both registers. |

Before control is enabled, writes to the register offsets only change backing RAM. Unknown commands clear the command and execution registers without changing results. RAM starts at zero and always contains 4 KiB, including when the ROM header declares none. Database SRAM-size overrides cannot remove this required workspace.

The frontend's existing `.srm` handling saves the shared RAM. Loading a save restores data without enabling the command registers. Reloading a cartridge clears protocol state and RAM before its save is restored.

## Commands

All offsets below refer to the shared RAM window. Words and longwords are little-endian.

| Command | Operation | Main inputs and outputs |
| --- | --- | --- |
| $01 | Heading | X/Y at $000/$002; reduced vector, quadrant, original Y, and angle at $000/$002/$004/$006/$010. |
| $02 | Driver order | Count at $024, positions at $040, driver IDs at $080. Sorts descending and preserves ties. |
| $03 | Coordinate scale | Signed X/Y and scale at $000/$002/$004; doubled 32-bit products at $010/$014. |
| $04 | Vector distance | Signed X/Y at $000/$002; integer distance approximation at $010. |
| $05 | Navigation | Updates position, heading, speed, target coordinates, and flags in $0C0-$0E1. |
| $06 | Multiply | Signed operands at $000/$002; doubled 32-bit product at $010. |
| $07 | Mode 7 raster | Angle at $000; 176 A/B/C/D words at $0F0/$250/$3B0/$510. Replaces the angle with its high byte. |
| $08 | Rotation | Signed X/Y and angle at $000/$002/$004; rotated coordinates at $010/$012. |

The implementation uses explicit integer wrapping for signed boundary cases. Driver counts above 32 are limited to the available entries, preventing malformed inputs from overrunning the workspace. This bound is a defensive choice; larger counts are not defined as supported hardware behavior.

Angle lookup tables are stored as integers. `python tools/generate_st010_tables.py` regenerates them from sine and arctangent curves plus fixed rounding corrections. Raster scale factors use rounded integer division, avoiding runtime floating-point calculations in commands.

## Validation and limits

Local comparisons covered 2,048 inputs per command, or 16,384 command runs. Every byte of the resulting 4 KiB RAM snapshots matched. Committed regression vectors retain a digest for each command and include signed boundaries, every angle-table entry, sorting ties, navigation branches, and unchanged memory around outputs.

Additional tests exercise register enable behavior, mirrored addresses, ROM and SRAM selection, open bus, shared save data, required RAM sizing, rejected ST011 loads, reloads, and a 65816 program that executes a command through the bus. All 17 Release suites pass. The ST010 and cartridge-device suites also pass under AddressSanitizer.

Both supplied games completed 1,800-frame smoke runs with visible video and non-silent audio. No ST010 game was available for testing, so this does not establish retail ST010 compatibility.

Commands complete immediately. Internal processor instructions, execution timing, and contention between the CPU and cartridge RAM are not modeled. ST011 and ST018 remain rejected, and the other unsupported cartridge processors listed in [compatibility notes](compatibility.md) still need implementations.
